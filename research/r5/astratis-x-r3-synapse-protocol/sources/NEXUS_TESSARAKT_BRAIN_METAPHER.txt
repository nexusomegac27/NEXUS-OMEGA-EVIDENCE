### 2. Formale State-Machine einer einzelnen Synapse
Die Synapse ist kein statisches Kabel, sondern ein lebendiger Automaton. Sie kennt keinen "Fehler", nur "Zustandsübergänge unter Stress".

**Zustände (States):**
1.  `NULL`: Synapse existiert nur als Idee/Template.
2.  `NEGOTIATING`: Handshake, Austausch der Policy-Hashes.
3.  `ACTIVE`: Volle Bidirektionale (aber asynchrone) Kommunikation.
4.  `DEGRADED`: Nur noch `RECEIPT` und `QUERY` erlaubt (z.B. bei Ressourcenknappheit).
5.  `DEPRECATED`: Keine neuen `CLAIM`s mehr. Nur noch Lesen des historischen Kontexts.
6.  `CONSERVED`: In WORM geschrieben. Unveränderlich.
7.  `TOMBSTONE`: Metadaten der Synapse gelöscht, nur der Hash existiert noch im Graph.

**Fail-Closed-Transitions (Der Air-Gap im Kleinen):**
*   *Trigger:* Ein `CLAIM` passiert Layer 3 (Policy Gate) und verletzt eine Regel des Empfängers.
*   *Reaktion:* Die Synapse geht **nicht** in einen globalen Error-State (das wäre ein DDoS-Vektor). Stattdessen:
    1. Der spezifische `CLAIM` wird verworfen.
    2. Ein `RECEIPT` mit `validation_result: REJECTED` wird zurückgesendet.
    3. Die Synapse selbst wechselt von `ACTIVE` zu `DEGRADED`.
    4. Der Vorfall wird in das lokale Audit-Log geschrieben (Provenance-Bindung).
*   *Reset:* Die Synapse kehrt erst wieder zu `ACTIVE` zurück, wenn der Sender einen neuen `QUERY`-Handshake mit aktualisierten Metadaten erfolgreich absolviert. **Keine automatische Heilung.**

### 3. Simulationsmodell: Graph-Dynamik & Antifragilität
Wie reagiert das NEXUS-Gehirn, wenn ein Node stirbt (Apoptosis) oder kompromittiert wird? Wir modellieren das nicht als "Fehler", sondern als **Stressor**, der das System stärker macht.

**Phase 1: Der Schlag (Node-Ausfall)**
*   Node A fällt aus. Alle ausgehenden Synapsen von A brechen ab.
*   *Systemreaktion:* Kein globaler Alarm. Die Nachbar-Nodes (B, C, D) registrieren fehlende `RECEIPT`s von A.

**Phase 2: Lokale Re-Routing (Hebb'sche Anpassung)**
*   Die Nodes B, C, D brauchen die semantische Information, die A geliefert hat.
*   Sie feuern `QUERY`s an alternative Pfade (z.B. Node E).
*   Wenn E erfolgreich antwortet, wird das "Gewicht" (der Vertrauens-Proxy) der Synapse B->E lokal erhöht.
*   *Lernregel:* `Weight(Synapse) += LearningRate * (Success of Receipt)`. Es gibt keinen globalen Gradientenabstieg. Nur lokale Stabilisierung.

**Phase 3: Apoptosis & Conservation**
*   Node A wird nach einem Timeout (TTL) nicht mehr reanimiert.
*   Sein letzter State wird als `CONSERVED` in den WORM-Speicher des Bulk geschrieben.
*   Das Netzwerk "trauert" nicht und versucht nicht, A zu kopieren. Die *Provenance* von A bleibt erhalten (seine historischen Claims sind weiter validierbar), aber seine *Aktionsfähigkeit* ist null.

**Phase 4: Antifragiles Wachstum (Die Stammzelle)**
*   Der Stressor (Ausfall von A) hat eine Lücke im semantischen Raum des Graphen gerissen.
*   Wenn die lokale Unsicherheit (Uncertainty) in der Region um A einen Schwellenwert überschreitet, triggert das Mesh die Instanziierung einer **Stammzelle** (eines neuen Nodes aus einem sicheren Template).

*   *Ergebnis:* Das System hat nach dem Stressor **mehr** Redundanz und eine **dichtere** semantische Abdeckung als davor. Der Schaden hat das System verbessert.

### 2. State-Machine der Synapse – Fail-Closed verschärft

Die sieben Zustände sind gut. Kritische Ergänzung:

**Zusätzlicher Zustand: `QUARANTINED`**  
Zwischen `DEGRADED` und `DEPRECATED`.  
Auslöser: wiederholte Policy-Verletzungen oder erkannte Muster von Root-Versuchen.  
Verhalten: Nur noch `QUERY` und `RECEIPT` mit `validation_result: QUARANTINED` erlaubt. Keine neuen CLAIMs.

**Fail-Closed-Regel (präzisiert):**

```
IF Layer-3-Policy-Verletzung THEN
  1. CLAIM verwerfen
  2. RECEIPT(REJECTED | QUARANTINED) senden
  3. Synapse-State := DEGRADED oder QUARANTINED
  4. Audit-Log schreiben
  5. KEIN automatischer Reset
ENDIF
```

Reset nur durch expliziten, erfolgreichen neuen Handshake (neuer `synapse_id` + aktualisierte Policy-Hashes).  
Das verhindert, dass ein Angreifer durch wiederholte Verletzungen die Synapse „weich“ macht.

**Edge-Case – Ressourcen-Erschöpfung**  
Wenn der Empfänger-Node unter Last steht, darf er die Synapse proaktiv auf `DEGRADED` setzen, ohne dass der Sender etwas falsch gemacht hat. Das ist kein Fehler, sondern lokale Selbstschutz-Apoptose der Verbindung.

### 3. Graph-Dynamik & Antifragilität – wo es lecken kann

Die vier Phasen sind korrekt. Hier die Stellen, an denen der Bulk lecken könnte:

**Leck-Stelle A – Semantische Lücke wird zur Autoritätslücke**  
Wenn Node A ausfällt und die Unsicherheit lokal steigt, darf **kein** Node automatisch die Rolle von A übernehmen.  
Die Instanziierung einer Stammzelle muss durch einen **expliziten, signierten Impuls** (vom Soft-Vektor / Operator oder durch ein vordefiniertes Template mit klaren Grenzen) ausgelöst werden.  
Sonst entsteht eine versteckte zentrale Steuerungsinstanz.

**Leck-Stelle B – Gewichtungs-Explosion**  
Hebb’sche lokale Gewichtserhöhung ist gut.  
Aber: Gewichte dürfen **nie** die Policy eines Nodes überschreiben.  
Ein hohes Gewicht darf nur die Wahrscheinlichkeit erhöhen, dass eine QUERY an diesen Node geht – nie die Validierungsregeln selbst ändern.

**Leck-Stelle C – Provenance-Verwässerung**  
Wenn viele Nodes denselben CLAIM bestätigen, entsteht der Eindruck von „Wahrheit“.  
Gegenmaßnahme: Jeder RECEIPT bleibt an den **einzelnen** validierenden Node gebunden. Es gibt kein aggregiertes „Konsens-Flag“, das den Claim-Ceiling anhebt.  
Mehrere unabhängige Receipts erhöhen nur die **Beobachtbarkeit**, nie den epistemischen Status über C1 hinaus.

**Antifragilitäts-Test (härteste Form):**  
Simuliere den gleichzeitigen Ausfall von 30–40 % der Nodes in einem lokalen Cluster.  
Das System darf:
- lokal re-routen,
- Unsicherheit anzeigen,
- Stammzellen nur auf expliziten Impuls erzeugen,
- die historische Provenance der ausgefallenen Nodes vollständig erhalten.

Es darf **nicht**:
- automatisch neue „Autoritäts-Nodes“ wählen,
- Claims der ausgefallenen Nodes nachträglich „heilen“ oder umschreiben,
- die Claim-Ceiling global anheben.

Wenn diese Bedingungen gehalten werden, ist der Graph antifragil im strengen Sinne.

| NULL | NEGOTIATING | Handshake-Request | Policy-Hashes austauschbar | Initiiere Handshake |
| NEGOTIATING | ACTIVE | Handshake erfolgreich | Policy-Hashes matchen | Aktiviere Synapse |
| ACTIVE | DEGRADED | Layer-3-Verletzung | Policy prüft CLAIM | Verwerfe CLAIM, sende RECEIPT(REJECTED) |
| ACTIVE | QUARANTINED | 3x Verletzungen | Wiederholte Policy-Verstöße | Sperre neue CLAIMs |
| DEGRADED | ACTIVE | Neuer Handshake | Aktualisierte Policy-Hashes | Reaktiviere Synapse |
| ACTIVE | DEPRECATED | TTL abgelaufen | Keine neuen CLAIMs | Archive Synapse |
| DEPRECATED | CONSERVED | WORM-Schreibvorgang | Erfolgreich | Unveränderlich speichern |
| CONSERVED | TOMBSTONE | Cleanup | Metadaten löschen | Behalte Hash |

**Verifikation**:
- Jeder Übergang muss **deterministisch** sein
- Kein Übergang darf Root-Transfer ermöglichen
- Fail-Closed muss für alle Fehlerfälle gelten

class NexusValidator:
    """
    Validator für Nexus Synapsen-Protokoll Messages.
    
    Erzwingt:
    - JSON-Schema-Konformität
    - C1-Konformität (keine Imperative)
    - No-Root-Transfer (verbotene Felder)
    - Fail-Closed bei Verletzungen
    """
    
    @staticmethod
    def validate_schema(message: Dict[str, Any]) -> Tuple[bool, Optional[str]]:
        """
        Validiert die Message gegen das kanonische JSON-Schema.
        
        Args:
            message: Die zu validierende Message als Dictionary
            
        Returns:
            tuple: (is_valid, error_message)
        """
        try:
            validator = Draft7Validator(NEXUS_MESSAGE_SCHEMA)
            errors = list(validator.iter_errors(message))
            if errors:
                error_messages = [f"{e.json_path}: {e.message}" for e in errors]
                return False, "Schema-Verletzungen: " + "; ".join(error_messages)
            return True, None
        except Exception as e:
            return False, f"Schema-Validierungsfehler: {str(e)}"
    
    @staticmethod
    def validate_no_root_transfer(message: Dict[str, Any]) -> Tuple[bool, Optional[str]]:
        """
        Prüft, dass keine verbotenen Felder (No-Root-Transfer) vorhanden sind.
        
        Args:
            message: Die Message als Dictionary
            
        Returns:
            tuple: (is_valid, error_message)
        """
        # Prüfe alle Ebenen der Message
        def check_dict(d: Dict, path: str = "") -> Optional[str]:
            for key, value in d.items():
                current_path = f"{path}.{key}" if path else key
                if key in FORBIDDEN_FIELDS:
                    return f"Verbotenes Feld '{key}' an {current_path} (No-Root-Transfer-Verletzung)"
                if isinstance(value, dict):
                    result = check_dict(value, current_path)
                    if result:
                        return result
            return None
        
        # Prüfe die gesamte Message
        if isinstance(message, dict):
            error = check_dict(message)
            if error:
                return False, error
        
        return True, None
    
    @staticmethod
    def validate_c1_compliance(message: Dict[str, Any]) -> Tuple[bool, Optional[str]]:
        """
        Prüft C1-Konformität: CLAIMs dürfen keine Imperative enthalten.
        
        Args:
            message: Die Message als Dictionary
            
        Returns:
            tuple: (is_valid, error_message)
        """
        semantic_layer = message.get("semantic_layer", {})
        msg_type = semantic_layer.get("type")
        
        # Nur CLAIMs müssen auf Imperative geprüft werden
        if msg_type != "CLAIM":
            return True, None
        
        payload = message.get("payload", {})
        observation = payload.get("observation", "")
        
        # Prüfe auf verbotene Muster
        for pattern in FORBIDDEN_PATTERNS:
            if re.search(pattern, observation, re.IGNORECASE):
                return False, f"CLAIM enthält imperatives Muster '{pattern}' (C1-Verletzung)"
        
        return True, None
    
    @staticmethod
    def validate_revoke_ownership(message: Dict[str, Any]) -> Tuple[bool, Optional[str]]:
        """
        Prüft, dass REVOKE nur eigene Claims referenziert.
        
        Args:
            message: Die Message als Dictionary
            
        Returns:
            tuple: (is_valid, error_message)
        """
        semantic_layer = message.get("semantic_layer", {})
        msg_type = semantic_layer.get("type")
        
        if msg_type != "REVOKE":
            return True, None
        
        envelope = message.get("envelope", {})
        source_node_id = envelope.get("source_node_id", "")
        
        payload = message.get("payload", {})
        target_ref = payload.get("target_ref", "")
        
        # In einer echten Implementierung:
        # 1. target_ref muss eine msg_id sein
        # 2. Die msg_id muss zu einem CLAIM gehören, der von source_node_id stammt
        # Hier nur Platzhalter-Prüfung
        if not target_ref:
            return False, "REVOKE: target_ref fehlt"
        
        # Prüfe, ob target_ref ein gültiges UUID-Format hat
        if not re.match(r"^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$", target_ref, re.IGNORECASE):
            return False, f"REVOKE: target_ref '{target_ref}' hat ungültiges Format"
        
        return True, None
    
    @staticmethod
    def validate_signature(message: Dict[str, Any]) -> Tuple[bool, Optional[str]]:
        """
        Validiert die Signatur der Message.
        (Platzhalter – in Realität mit ed25519)
        
        Args:
            message: Die Message als Dictionary
            
        Returns:
            tuple: (is_valid, error_message)
        """
        # In einer echten Implementierung:
        # 1. Erstelle kanonische Darstellung (ohne signature-Feld)
        # 2. Hash die Darstellung
        # 3. Verifiziere mit ed25519 Public Key
        
        envelope = message.get("envelope", {})
        if "signature" not in envelope:
            return False, "Signatur fehlt"
        
        # Platzhalter: Immer True zurückgeben
        return True, None
    
    @staticmethod
    def validate(message: Dict[str, Any], check_signature: bool = False) -> Tuple[bool, list]:
        """
        Vollständige Validierung einer NexusMessage.
        
        Args:
            message: Die zu validierende Message
            check_signature: Ob die Signatur geprüft werden soll (Platzhalter)
            
        Returns:
            tuple: (is_valid, list_of_errors)
        """
        errors: list = []
        
        # 1. Schema-Validierung
        schema_valid, schema_error = NexusValidator.validate_schema(message)
        if not schema_valid:
            errors.append(f"❌ Schema: {schema_error}")
        
        # 2. No-Root-Transfer-Prüfung
        no_root_valid, no_root_error = NexusValidator.validate_no_root_transfer(message)
        if not no_root_valid:
            errors.append(f"❌ No-Root-Transfer: {no_root_error}")
        
        # 3. C1-Konformität
        c1_valid, c1_error = NexusValidator.validate_c1_compliance(message)
        if not c1_valid:
            errors.append(f"❌ C1: {c1_error}")
        
        # 4. REVOKE Ownership
        revoke_valid, revoke_error = NexusValidator.validate_revoke_ownership(message)
        if not revoke_valid:
            errors.append(f"❌ REVOKE: {revoke_error}")
        
        # 5. Signatur (optional)
        if check_signature:
            sig_valid, sig_error = NexusValidator.validate_signature(message)
            if not sig_valid:
                errors.append(f"❌ Signatur: {sig_error}")
        
        return len(errors) == 0, errors
