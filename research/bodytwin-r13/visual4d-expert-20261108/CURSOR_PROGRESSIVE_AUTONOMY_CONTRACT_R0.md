## Decision engine and negative evidence
1. Classify each incoming request and each failure by impact: read-only/reversible public C1/irreversible or sensitive.
2. Search known GitHub issues and source/receipts before inventing files or structures. Keep one canonical branch per bounded feature and one append-only receiver.
3. Independently reproduce once; generate negative fixture for every observed unexpected acceptance. No forced productive reruns just to make tests green.
4. For each candidate compare baseline to change in: numerical SO(4) fidelity, existing five projection modes, six sliders, mobile input, 4D output, public GET feed and CSP.
5. Auto-resolve A0/A1/A2 blockers (missing import, broken path, absent test dependency, UI overflow, regression). Stop only on evidence gaps that genuinely change authority/truth/safety.
6. Always preserve baseline and rollback; treat source GitHub push, host deployment, HTTP byte match, DOM, and research truth as distinct receipts.
7. If the same test/regression fails repeatedly without new information, switch strategy or seek expert rebuttal; no infinite repetitive test loops. Report blocker once with reproducible minimal counterexample and a recommended next action.
8. Maintain a durable backlog of small improvements in GitHub, with ranks based on risk reduction, user-visible gain, implementation cost, dependency coupling, and scientific claim risk.
