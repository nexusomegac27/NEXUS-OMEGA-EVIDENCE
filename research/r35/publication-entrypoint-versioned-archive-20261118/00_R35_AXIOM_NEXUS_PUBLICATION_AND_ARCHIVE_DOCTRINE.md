## Operator's binding design principles
1. nexus-mobile.de is a STRICTLY STRUCTURED ENTRY PLATFORM, not an undifferentiated laboratory dashboard or news ticker.
2. Every publication is a CAUSAL EVENT, whether its scientific content is subsequently confirmed, rejected or corrected. A superseded belief must never silently vanish.
3. Outdated information MUST leave the ACTIVE presentation and move to an EXPLICIT RETRIEVABLE ARCHIVE, with stable URL, original immutable record, effective dates, correction/supersession links, independent source SHA-256 and reader-facing historical status.
4. An unresolved CURRENT negative result, falsifier or HOLD is active evidence and MUST NOT be disguised as old or archived merely because it is uncomfortable.
5. No auto-release, secret exposure, clinical claim, external agent write permission, public-deploy authorization or promotion follows from this design note.

## Minimal visitor-first navigation proposal
HOME: 1-line project purpose; exact R35 current primary focus OPPO/BODYTWIN with BODYTWIN_VALIDATED=NO and relevant open challenges; three links: Current Research, Open Questions, Historical Archive.
CURRENT RESEARCH: curated source-bound projects, each an explicit latest approved PUBLICATION POINTER, next evidence gate, visible source date/freshness and canonical link. Show OPPO/BODYTWIN prominently, supporting Memory and Public Science Updates subordinate.
OPEN QUESTIONS: current unresolved blockers, negative findings and counterexamples (NIS caveats, measurement reference, BODYTWIN validation, memory privacy), not success-only.

Evidence, Forum, ORBIS, CUSTOS, Agent Border, Terminal and the public AI source feed remain reachable in secondary NAV / specific tracks, but are not equal-priority landing hero surfaces.

## Strict rules for archived entries
- Archive is a separate browse surface, not a hidden section under ACTIVE and not deletion. Historical source bytes retained in legally permitted original custody.
- On old URL show the historical page in place if safe, with prominent warning 'ARCHIV / HISTORISCH — NICHT AKTUELL' plus link to new status; do not silently replace the old text with the current version.
- Archive record contains immutable original hash, public-safe source URI, published_at, archived_at, as_of_at, state, reason_code, relation type, next current pointer, original claim ceiling, evidence class, operator decision and privacy/access class. Preserve previous negative evidence.
- Distinguish SUPERSEDED_BY_NEW_EVIDENCE, REFUTED_BY_COUNTEREXAMPLE, WITHDRAWN_FOR_SAFETY, STALE_SOURCE_SNAPSHOT, and HISTORIC_NOT_CURRENT. This is not the same as destructive retraction.
- Never claim a positive new publication exists if the replacement has no independently verified source object. In that case show archived historical source and explicit CURRENT_STATUS_UNAVAILABLE; do not fabricate a redirect.
- A stale runtime panel is NOT itself a source-validity verdict. Mark source_generated_at, fetched_at, explicit freshness, and last corroborated status separately. An outdated status cannot be rendered as today's scientific result.
- Private OPPO sensor, human biometric, security credentials and private CAS hashes must NOT leak via public archive, public indexes, preview cards, redirects, responses or search errors. Legal removal/secret-redaction may require a documented safe substitute; never force continued public display of restricted material.
- Preserve independent negative results and corrected misconceptions using append-only CORRECTS, REFUTES, SUPERSEDES, and DERIVED_FROM edges. Hash-match proves source custody only.
