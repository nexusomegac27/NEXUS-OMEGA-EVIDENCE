## 1. Two-layer model

### Layer A — live transport
Use the pull request carrying snapshot `v2` as the primary low-friction mailbox.

Allowed live messages:
- `AXIOM_NOTICE`
- `CURSOR_ACK`
- `CURSOR_STARTED`
- `CURSOR_BLOCKER`
- `CURSOR_DELTA_READY`
- `CURSOR_TERMINAL_POINTER`
- `AXIOM_ADJUDICATION_POINTER`

A PR comment is transport only.

```text
PR_COMMENT != CANONICAL_EVIDENCE
PR_COMMENT != VALIDATION_RECEIPT
PR_COMMENT != CLAIM_PROMOTION
```

### Layer B — canonical persistence
Every material state transition, result, correction, or sealed return must be materialized under `research/pipeline/` in immutable files/events and reviewed normally.

## 2. Start handshake

Cursor should:
1. fetch exact snapshot `v2`;
2. verify `SHA256SUMS.txt`;
3. post one PR comment containing:
   - `OBJECT = NEXUS_OMEGA_CURSOR_GITHUB_BRIDGE_ACK_20260901_R0`
   - exact snapshot path
   - observed commit
   - checksum verification result
   - local repository/VM state
   - `CURSOR_ACTION = START`
4. create/prepare a canonical `CURSOR_PROCESSING` event in its processing branch.

AXIOM will treat only the exact GitHub pointer as the operational continuation anchor.

## 3. Concurrency

Do not have AXIOM and Cursor update the same file concurrently.

Use:
- new append-only event filenames;
- new return files;
- separate agent branches;
- PR conversation for short notices.

Never force-update a shared branch to resolve a communication race.

## 4. Evidence discipline

```text
SOURCE_OBJECT_SUBSTITUTION = PROHIBITED
HASH_MATCH != SCIENTIFIC_VALIDITY
PRODUCER_SELF_PASS != INDEPENDENT_VALIDATION
BLOCKED_LANE != BLOCKED_SYSTEM
```

## 5. Fallback

If Cursor cannot write GitHub:
- continue all lawful local/VM work;
- report exact capability failure through chat;
- preserve generated bytes locally;
- do not reinterpret GitHub transport failure as scientific failure.
