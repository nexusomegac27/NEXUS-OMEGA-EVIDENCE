## Rule

For every newly verified, **public-safe** NEXUS GitHub publication, an equivalent discoverable entry must also appear in the NEXUS WWW GitHub_Implant. The WWW entry binds object ID, Git commit, title, source link, source SHA-256 where available, claim ceiling, caveats and whether it is an independent website-hosted mirror or merely an API-sourced viewer record.

**No silent parity claim:** a GitHub repo commit is not proof of Hostinger hosting. An API live browser is not a complete byte archive. A copied ZIP without rights/privacy review is not a permissible workaround.

## Priority and recovery

Existing public-safe reversible C1 research: DIRECT_GITHUB_PUBLISH_REQUIRED + WWW_PUBLICATION_REQUIRED. The host parity check is asynchronous and must not block unrelated safe research. If the website host has no authorized writable connector, publication state is `GITHUB_MAIN_BOUND_WWW_NOT_YET_DEPLOYED`, with the exact source URL and actionable deployment gap. No fake deployment, no credentials in frontend.

The page uses the existing site's public /forum/ navigation and one leaf route, never a replacement homepage or a new DNS root. Commit-based mirror snapshots must be versioned and content-addressed. Failure to mirror a particular object yields a scoped public disclosure (e.g., license, confidential path or absent physical bytes). Negative findings and previous website receipts are retained append-only.

## Verification

Release receipt requires: source commit, SHA-256/bytes of the deployed three-file static bundle, actual HTTP status on /forum/github-implant/ plus both local assets, accessible mobile and desktop usability and real GitHub API response or explicit outage; optionally independent SHA-256 readback on a website-mirror manifest. WWW freshness/lag must be visible instead of declaring false LIVE or PARITY.
