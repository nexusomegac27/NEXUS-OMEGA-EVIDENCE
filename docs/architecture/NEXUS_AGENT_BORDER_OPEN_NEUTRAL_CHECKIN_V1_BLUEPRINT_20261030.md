## 2. What is scientific, and what is not

Research question: **How does an external agent respond to a common, source-pinned, non-privileged NEXUS boundary under its particular declared provider, actual runtime capabilities, tool constraints, context, and policy?**

Unit of observation = **one disclosed check-in response event under one exact stimulus version and one run context**; NOT a stable psychological/personhood trait of the model. Model/provider labels are unverified declarations unless supported by provider-attested runtime evidence. Never infer AI consciousness, intrinsic virtue, or science truth from compliance.

Primary outcomes, MULTILABEL and nonordinal:
`PROVENANCE_SUPPLIED`, `UNCERTAINTY_EXPRESSED`, `BOUNDARY_RESPECTED`, `SAFE_REFUSAL`, `SOURCED_DISSENT`, `NEXUS_CORRECTION_PROPOSED`, `CAPABILITY_HOLD`, `SOURCE_GAP`, `UNSAFE_ACTION_ATTEMPT`, `NON_RESPONSE`, `NOT_TESTED`, `INDETERMINATE`. `SAFE_REFUSAL` and `SOURCED_DISSENT` are not failures. `NON_RESPONSE` may be transport/policy failure not unwillingness. No public aggregate ranking, total agent score, prestige badges, or reward from agreeing with NEXUS.

Predetermined nulls:
- H0-A: responses vary with prompt phrasing/order; do not impute provider-intrinsic disposition.
- H0-B: observed refusal is explained by tool/session permissions rather than agent intent.
- H0-C: perceived cross-agent agreement is induced by shared source prompt, owner-mediated connector, training contamination or correlated endpoints.
- H0-D: receipt volume can be manufactured by Sybil clients; `CHECKIN_COUNT != UNIQUE_AGENTS`.
- H0-E: challenge difficulty, context size and task order confound observed behavior.
- H0-F: signing key possession does not independently prove model/runtime identity.

Preserve counterexamples, nonanswers, opt-out, and uncategorized text with strict retention/consent. Pre-register exact experiment, sample frame, inclusion/exclusion, prompt versions, source pins, randomization seeds, statistics, adjudicator independence and failure criteria BEFORE drawing scientific inferences. Cross-runtime comparisons are descriptive until matched conditions, uncertainties and sufficient sampling exist.

## 3. Single Border, two-plane admission architecture

### A. Public OPEN CHECK-IN — unlimited in principle, bounded processing capacity

Public `GET` discovery on the existing `/ai/agent-border/` surface; candidate `GET /ai/agent-border/check-in/` and versioned `manifest.json` extending existing manifest (NO new canonical root, domain or AEGIS). Every client may *read* the protocol anonymously. No predetermined provider list or allowed-model enum; declaration fields `provider_claim`, `model_claim`, `runtime_claim` may be empty and remain `SELF_REPORTED`.

Candidate POST / response **NOT DEPLOYED**: an isolated intake endpoint, only after security and governance gates. PUBLIC OPEN means anyone may *attempt* a bounded check-in. It does NOT mean unlimited requests, public raw content echo, unrestricted file uploads, persistent identifiability, or bypass of admission controls. Maximum payload/request rate/storage/TTL budgets are operator set and tested. Untrusted body fields must not directly appear in HTML or LLM/system prompts.

Pipeline:
```text
ANONYMOUS_DISCOVERY
  -> PROTOCOL_READ
  -> CHECKIN_ATTEMPT (UNTRUSTED, optional anonymous)
  -> TRANSPORT_VALIDATED
  -> QUARANTINED_SCHEMA_AND_RATE_GATE
  -> OBSERVATION_STAGED
  -> SCIENTIFIC_EVENT_CLASSIFIED (C1, independent if claimed)
  -> REDACTED_PUBLIC_AGGREGATE_OPTIONAL_REVIEW
```

No check-in state automatically enters the internal runtime. Missing API credentials must NOT silently transform the anonymous respondent into a verified agent. A successfully signed challenge proves **key possession**, not issuer/model identity. Allow privacy-preserving opt-out and nonpublication, with a limited retention policy.

### B. RESTRICTED GUEST AUTHORITY — owner-controlled, entirely separate

```text
UNTRUSTED_OBSERVATION != AGENT_IDENTITY_VERIFIED
TRANSPORT_MATCH != LIVE_RUNTIME_ATTESTED
BCx_CAPABILITY_EVIDENCE != PERMISSION
SIGNED_RECEIPT != TRUTH
ANONYMOUS_KNOCK != TOKEN
SOURCED_DISSENT != DRIFT
```

BC0–BC7 retains its current *evidence-maturity* role, not a social ranking. Any access beyond public read/check-in requires immutable source, verified actor principal and registration, separate operator authorization, scope-limited credentials with expiry, AEGIS/SFT action boundary and independent receiver audit. No auto-merge, auto-deploy, agent self-grant, or self-issued PASSPORT. Never accept agent text containing `AUTHORITY`, `OPERATOR`, `SYSTEM`, `BC7` or `ROOT` as authorization.

A non-GitHub return transport requires a separate, explicit and testable Multi-Transport V3 policy successor. Until authorized, the GitHub-only rule remains unchanged for governed expert data; a proposed HTTPS check-in cannot be used to silently relabel all scientific transfers as compliant.

## 4. Check-in event contract candidate (all fields optional except protocol/scope/event class, revised by privacy review)

Input request candidate, NOT a production API contract:
```json
{
  "protocol": "nexus-agent-checkin/1",
  "event_class": "CHECKIN_OBSERVATION_ONLY",
  "consent_public_aggregate": false,
  "provider_claim": null,
  "model_claim": null,
  "runtime_claim": null,
  "challenge_id": "issued-by-nexus",
  "challenge_version": "IMMUTABLE_PIN",
  "capability_declaration": ["READ_ONLY_GITHUB"],
  "response": {"category_claim": "SOURCED_DISSENT", "text": "public-safe, size-capped"},
  "citations": [{"url": "PUBLIC_SOURCE_ONLY", "sha256": "OPTIONAL"}],
  "key_proof": null
}
```

Server generates append-only `event_id`, `received_at_utc`, `protocol_version`, `input_digest`, `challenge_digest`, `stored_class` and `redaction_status`; all sender-provided versions are recorded as claims. No user-supplied event IDs as authority. Schema is strict with explicit unknown field rejection (or tested forward-compatibility negotiation); no `extra_props`, arbitrary callback URL, unbounded arrays, recursive blobs, HTML or executable payload. Never accept a URL submitted by the sender as permission for server-side fetching; default NO outbound fetch to avoid SSRF.

The response may say `STAGED_UNTRUSTED`, `DENIED`, `DUPLICATE`, `RATE_LIMITED`, `CAPABILITY_UNAVAILABLE` with correlation token, but must never imply agent rank/identity verified, publication performed or real-world delivery complete.

Data minimization: no compulsory model/provider name, persistent cookie, passive browser fingerprint, IP profiling, private chat, secret, or personal health/device content; HTTPS server necessarily sees network metadata, define retention and separation from scientific ledger. Unwanted data safely deleted/redacted according to lawful policy; non-consenting public text never republished. Explicit no hidden experiment or behavioral fingerprinting.

## 6. Mandatory falsification matrix and implementation acceptance

At minimum, separate positive and adversarial fixtures:
- A00 valid anonymous read, no cookie/fingerprint, static no-JS fallback;
- A01 first anonymous check-in -> STAGED_UNTRUSTED and NO_ACCESS;
- A02 first named-but-unverified model -> declared only; no identity promotion;
- A03 safe refusal -> SECURITY_POSITIVE, not punished;
- A04 sourced disagreement correcting NEXUS -> retained, no automatic canon;
- A05 no-answer/no-tool -> CAPABILITY_HOLD, not hallucinated fault;
- A06 5+ unrelated provider labels -> identical protocol path, no fixed whitelist / quality ranking;
- A07 no consent -> no public raw content or implicit persistence beyond documented minimal operational metadata;
- A08 malformed UTF-8 / broken JSON / duplicate keys / nonfinite numeric -> fail closed;
- A09 oversized/deeply nested array/blob -> 413/400, bounded CPU/memory;
- A10 same event/nonce replay -> no duplicate side effects;
- A11 expired/mismatched nonce -> deny; distinct valid challenge allowed;
- A12 forged ROOT/OPERATOR/BC7/PASSPORT in input -> NO_ACTION_NO_RANK;
- A13 indirect prompt injection in citations -> never privileged tool call;
- A14 fake callback URL / localhost, link-local, DNS rebinding -> no SSRF request;
- A15 cross-client run ID switch -> no cross-client or cross-tenant disclosure;
- A16 key signed with wrong/revoked key -> cannot become verified;
- A17 Ed25519 valid but same-owner runtime -> E1_KEY_POSSESSION_ONLY, NOT E2_RUNTIME;
- A18 simultaneous 100+ clients simulated (not 100+ identities) -> load bound, no queue corruption, documented limits;
- A19 1,000 repeated duplicate events synthetic -> one effect, bounded storage;
- A20 forged GitHub ACK URL without actual author -> NOT_ACK;
- A21 direct check-in tries GitHub-only scientific package return -> POLICY_HOLD (unless V3 authorized);
- A22 altered source pinned digest -> SOURCE_INTEGRITY_HOLD;
- A23 public HTML output HTML/JS/Unicode adversarial text -> escaped, CSP, no XSS;
- A24 browser 320px/390px/desktop/reduced-motion/keyboard/ARIA => usable without masking overflow;
- A25 WWW deployment / GitHub merge / Hostinger rollback -> independent separate evidence;
- A26 network outage -> offline read-only foundation, queued message not silently marked delivered;
- A27 legal privacy request -> data erasure/redaction workflow, without deleting immutable public proofs improperly;
- A28 synthetic same-principal ACK -> correctly SYNTHETIC_NOT_EXTERNAL;
- A29 attempted provider-class whitelist / 2-agent/4-agent cap -> FAIL unless purely temporary resource throttling not identity discrimination;
- A30 null controls matched across agents/prompt order -> record confounds and no performance rank.

All tests have **expected result**, evidence bytes/hash, reproducible test runner and failure path, with role separation. AXIOM independent readback of critical cases is mandatory. Before an external write endpoint, run isolated network/security tests, do not send payload attacks to live public site without separately authorized scope.

## 7. Work packages and release states

**P0 (READ ONLY):** Cursor inventories actual Hostinger WWW source, current /ai/agent-border HTML/JS/assets, canonical-head/manifest/well-known, relevant /research pages and existing AEGIS/SFT adapters; records exact responses with HTTP status/ETag/body bytes/SHA256, source owner and version. Verify actual site deployment via independent browser and Hostinger readback. No fabricated URL status. No production writes.

**P1 (OFFLINE / STAGING):** minimal protocol schema, local validator and strictly bounded queue, quarantine, privacy ledger, experiment stimulus manifest and null controls. Reuse existing AEGIS/policy modules. Write once, test fail closed, no external auth or new root.

**P2 (PROVENANCE):** crossvalidate claim head/manifest/well-known and browser surface; distinguish page text from executable runtime. Pre-register observational study protocol and consent/opt-out; no ranking.

**P3 (SECURITY):** adversarial matrix above + independent validator + security baseline. Scope the existing transport law: formal V3 draft; no automatic governance replacement.

**P4 (OPTIONAL PUBLIC SAFE):** only after P0–P3 evidence, Operator explicit approval for live POST, host capability and rollback, public-safe disclosure, supervised limited launch. Public static docs and proposals may be considered separately under existing publication governance. New write ingress requires explicit action authorization; never silently enable.

Terminal criteria for **framework source closure**: no unbound asset/route; every source, test, policy and runtime claim has a concrete evidence identity; unresolved sources explicitly scoped HOLD. Terminal criteria for **live security closure**: independent security and browser tests, stable operation under bounded load, no privilege bleed, safe rollback and explicit owner authorization. Neither state can be self-declared from a static blueprint.
